# 엑셀 데이터 작성 가이드

이 폴더의 엑셀 파일을 수정해서 `main`(또는 작업 브랜치)에 push하면, GitHub Actions가 자동으로 XML/코드로 변환해서 커밋까지 해줍니다. 더 이상 별도 툴을 실행하거나 배포된 프로그램을 받아서 쓸 필요가 없습니다.

## 1. 자동 변환(GitHub Actions)이 언제, 어떻게 동작하나

- **트리거**: 이 폴더(`Data/Excel/**`) 안의 파일이 바뀐 채로 push되면 자동 실행됩니다. (`.github/workflows/excel-convert.yml`)
- **하는 일**: 모든 엑셀을 읽어서
  1. `Assets/Resources/XML/*.xml` 갱신
  2. `Assets/Scripts/Data/DataDrivenDefines.cs`, `DataEnumDefines.cs` 갱신
  3. 바뀐 게 있으면 자동으로 커밋 (커밋 작성자: `github-actions[bot]`)
- **참조 오류(ID 참조가 깨진 경우)가 있어도 변환은 그대로 진행됩니다.** 다만 Actions 로그에 경고 목록이 남으니, 내 작업이 끝난 뒤 한 번씩 로그를 확인해서 오타/누락이 없는지 보는 걸 권장합니다.
- 엑셀 파일 자체가 깨졌거나(예: 열려 있는 상태로 커밋됨) 타입 표기가 아예 잘못된 경우처럼 "읽을 수조차 없는" 문제는 Actions가 **실패**로 표시됩니다. 이 경우엔 커밋이 안 올라가니 로그를 보고 고친 뒤 다시 push하면 됩니다.

즉 기획자 입장에서 해야 할 일은 딱 하나, **엑셀을 규칙대로 작성해서 push하는 것**뿐입니다.

## 2. 로컬에서 미리 확인하고 싶을 때

push하기 전에 미리 결과를 보고 싶다면 (닷넷 SDK가 설치되어 있어야 함):

```
dotnet run --project Tools/ExcelDataTool
```

저장소 루트 아무 위치에서나 실행하면 됩니다. 결과 XML/코드가 바로 갱신되고, 콘솔에 변환 로그와 경고가 출력됩니다.

> 엑셀 파일을 열어둔 채로 실행하면 "파일을 읽을 수 없습니다" 에러가 납니다. 엑셀을 닫고 다시 실행하세요.

## 3. 엑셀 시트 작성 규칙

- **1행**: 컬럼명
- **2행**: 타입 선언 (아래 표 참고)
- **3행부터**: 실제 데이터
- 모든 테이블은 `ID`라는 이름의 컬럼이 반드시 있어야 합니다 (대소문자 무관).

### 지원 타입

| 타입 | 표기 (2행에 적는 값) | 데이터 예시 |
|---|---|---|
| 정수 | `int` | `10` |
| 실수 | `float` | `0.1` |
| 불리언 | `bool` | `True` |
| 문자열 | `string` | `Recipe1` |
| 날짜 | `date` | |
| enum | enum 이름 그대로 (예: `ENUMGRADE`) | `GOOD` |
| 정수 배열 | `int[]` | `{1;179}` |
| 실수 배열 | `float[]` | `{1.5;2.0}` |
| 문자열 배열 | `string[]` | `{a;b;c}` |
| 다른 테이블 ID 참조 | `id:테이블명` | `Item1` |
| 다른 테이블 ID 배열 참조 | `id[]:테이블명` | `{drop1;drop2}` |
| 기획자 전용 메모 (변환 안 됨) | `design` | 아무 내용이나 |

배열 값 구분자는 `;`, `,`, 공백 다 됩니다. 다만 저장될 때는 `{a;b;c}` 형태로 통일됩니다.

### enum 쓰는 법

1. `DataEnumDefines.xlsx`에 탭을 하나 추가합니다. 탭 이름은 `EnumXxx` 형태로 (예: `EnumWeaponType`).
2. 그 탭에 1열 = 이름, 2열 = 값으로 데이터를 채웁니다.
3. 다른 테이블의 타입 행(2행)에 탭 이름을 대문자로 이어붙인 이름(`ENUMWEAPONTYPE`)을 적으면 그 enum 타입으로 잡힙니다.

### 다른 테이블 ID 참조하는 법 (`id:`, `id[]:`)

`테이블명`은 참조하려는 엑셀 파일명(확장자 제외, 대소문자 무시)입니다.

```
Drop.xlsx
      ID       ITEMID
타입   string    id:Item
데이터  drop1     Item1

Hunting.xlsx
      ID          DROP_ID
타입   string       id[]:Drop
데이터  Hunting1     {drop1;drop2;drop3}
```

- 참조한 테이블에 그 ID가 실제로 없으면(오타 등) **변환은 되지만 경고**로 남습니다. Actions 로그에서 확인하세요.
- 참조할 항목이 없는 경우(빈 값 대신 명시적으로 "없음"을 표시하고 싶을 때)는 `NONE`이라고 적으면 검증에서 제외됩니다.

### 참조를 한글 이름으로도 쓰고 싶을 때 (`ID_DEV`)

테이블에 `ID_DEV`라는 이름의 컬럼(타입은 `string`)을 만들면, 그 값을 한글 등 알아보기 쉬운 이름으로 채워둘 수 있습니다. 이 컬럼 자체는 게임 데이터로 나가지 않지만(XML에서 빠짐), **다른 테이블에서 `id:`/`id[]:`로 참조할 때 실제 ID 대신 이 이름으로 써도 됩니다.** 변환할 때 자동으로 실제 ID로 바뀝니다.

```
Item.xlsx
      ID      ID_DEV   NAME
타입   string   string   string
데이터  Item1    곰고기     고기

Drop.xlsx
      ID      ITEMID
타입   string   id:Item
데이터  drop1    곰고기     ← 저장되는 XML엔 자동으로 Item1로 바뀜
```

### 한 파일에 탭을 여러 개 쓰고 싶을 때 (예: `BBString`)

`BBString.xlsx`처럼 카테고리별로 탭을 나눠도 됩니다. 단, **모든 탭이 컬럼 구성(개수·이름)이 완전히 같아야** 하고, 결과적으로 하나의 테이블(`BBString`)로 합쳐집니다. 다른 테이블에서 `id:BBString`이라고 쓰면 어느 탭에 있는 ID든 상관없이 찾아줍니다.

## 4. 자주 하는 실수

- `ID` 컬럼 자체를 `id:테이블명`처럼 쓰지 않기 — 자기 자신의 ID는 그냥 `string`(또는 테이블명 없이 `id`)이면 됩니다. `id:`/`id[]:`는 **다른 테이블을 참조하는 컬럼**에만 씁니다.
- `ID_DEV`, `design` 타입 컬럼은 게임에서 안 쓰이니 오타 걱정 없이 자유롭게 메모용으로 써도 됩니다.
- 엑셀을 열어둔 채로 push/로컬 실행하지 않기 — 파일이 잠겨 있으면 변환이 아예 실패합니다.
